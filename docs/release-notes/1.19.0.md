This release lets a percentage-of-energy tariff vary over the day, as a per-kWh tariff already could. If any of your tariffs has a band that crosses midnight, such as a 22:00–06:00 low tariff, read the first fix below: those hours were billed at the wrong rate.

### Percentage tariffs with time-of-use bands

A **Percentage of energy tariffs** tariff used to carry a single percentage, applied to the grid price at every hour. It is now priced by bands, entered in the same **Add Period** dialog a per-kWh tariff uses, with the same time windows, weekdays and months. The difference is that each band takes a percentage instead of a CHF/kWh price. At each timestamp the matching band's percentage is applied to the grid price at that timestamp. This lets you make local energy cheap at midday and dearer in the morning and evening, for example 90 % until 10:00, 60 % until 16:00 and 90 % until midnight, and still follow the grid price.

When you create a percentage tariff, its **Initial percentage** becomes one flat band. To split it, open the tariff under **Tariffs** and use **Add Period**. Existing percentage tariffs are converted to a single flat band on upgrade and bill exactly as before. With **Itemise price bands on the invoice** switched on, a percentage tariff now gets one invoice line per band. With it off, the tariff gets one line, which shows the blended average percentage when the bands differ. The contract PDF and the tariff overview PDF list one row per band.

Bands follow the per-kWh rules exactly. That includes the fallback: an hour that no band covers is billed at the tariff's first band, so make the windows cover all 24 hours. A tariff that has bands cannot change its billing mode until you remove them. Nothing checks a higher evening percentage against the Art. 16 EnV price ceiling; that is still open as #690.

### Also new

- Participants read their **Annual Statement** and **Tax Overview** on the **Reports** page, each in its own tab, instead of only downloading them
- The **Available Fields** panel in the PDF and email template editors, and in the invoice-email fields under **Settings → Documents & emails**, can be searched and shows sample values. Clicking a field inserts it at the cursor. The onboarding email's `{expiry_date}` is now listed
- Under **Settings → Documents & emails**, empty invoice-email fields show the admin's global template as a placeholder, so you can see what is sent when you leave them blank
- ZEV owners now see deletions of their own metering imports in their audit log. Deletions made before this release remain visible to admins only
- The account and community menus in the header work from the keyboard: opening one moves focus into it, and Escape returns focus to the button
- The user guide is published at https://www.openzev.ch/docs/, and **Getting Started** has a new section on installing for production

### Fixes worth knowing about

- **Tariff bands that crossed midnight never matched.** A band such as 22:00–06:00, or one ending at 00:00, matched no hour. Those hours were billed at the tariff's fallback band, so a typical HT/NT tariff billed the whole night at HT. Such windows now wrap past midnight. The weekday is the timestamp's own: a Monday–Friday 22:00–06:00 band covers Friday night up to midnight and the early hours of Friday, but not Saturday morning. Tariffs imported from a VSE file already split these windows and were not affected. To check, look in **Tariffs** for a band whose end time is at or before its start time. Invoices already issued keep their amounts; invoices generated or regenerated after the upgrade use the band's own price.

### Upgrading

There are two migrations, both in `tariffs`, and they rewrite data. `0018_percentage_bands` adds a percentage to tariff bands, makes the CHF/kWh price optional, and turns each percentage tariff's value into one flat band. `0019_percentage_bands_constraint` requires every band to have exactly one of the two, and removes the percentage from the tariff itself. They touch only percentage tariffs and should run in seconds. If you roll back, a tariff that has several bands collapses to one percentage.

**Breaking API change:** tariffs at `/api/v1/tariffs/tariffs/` no longer have a `percentage` field. If a script sends it, the field is ignored without an error. To set the starting value, create the tariff with `initial_percentage`. To change percentages afterwards, update the bands at `/api/v1/tariffs/periods/`, each of which has a `percentage`.

ZEV transfer archives are now exported as format version 4. This release still imports versions 1–3, but an older instance rejects a version 4 archive, so upgrade the receiving instance first.

There are no configuration changes.
