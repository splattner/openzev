This release rebuilds the two metering screens — **Metering Data** and **Metering Points** — around finding the meter that needs attention rather than reading numbers off a table. It also corrects the VAT percentage printed on invoice PDFs, which needs a manual step if you run a custom template.

### Chart a whole community, not one meter at a time

The metering-point selector gains **Whole ZEV total (all meters)**, which sums every meter in the selected community into one series. Until now the page could only chart one meter at a time.

The stat cards now also show average and peak consumption per bar, and the peak card names the day or hour it fell on.

The meter dropdown lists each meter's type, active state and community instead of a bare meter ID. Picking a period with no readings is no longer a dead end: if the meter has data elsewhere, the empty state offers to jump to the range it actually covers. The selected period now travels in the URL along with the meter, so a link to a specific meter and quarter can be shared or bookmarked.

The whole-ZEV total is available to admins and ZEV owners with a community selected, and it deliberately has no raw-readings table beneath it — individual readings only mean something for one physical meter.

### Readings that flag their own problems

The **Raw Data by Day** table now marks days that look wrong: a day with an assignment holder but no energy at all, and a day whose consumption or feed-in total is negative. Opening a day additionally flags negative individual readings and duplicate timestamps, which were previously summed together and disappeared.

Each day's totals are shaded in proportion to the largest day in the period, so an outlier is visible without reading every row, and long periods are paginated a month at a time.

These are a fixed set of checks, not statistical outlier detection — an implausible but positive reading still needs a human eye.

### Data Quality points at the meter that needs work

The three severity cards are now filters: click one to narrow the table to it, click it again to clear. Every column sorts, with the status column ordering worst-first, and a meter's full gap list expands in place rather than ending at "+2 more". Clicking a meter ID jumps to that meter's chart for the same period.

### Metering Points shows data health on the list

The list is now identity-first cards carrying each meter's reading coverage, its most recent reading, and whether anyone currently holds it — an unassigned meter records energy that gets billed to nobody, and that was previously invisible here. The summary counts double as filters, and the active filters persist in the URL.

### Also new

- The metering-point list is now filtered by community on the server rather than fetched whole and narrowed in the browser
- The chart's data-point count is labelled by what it counts — days, hours or months shown — instead of the ambiguous "Data points"

### Fixes worth knowing about

- **Invoice PDFs printed the wrong VAT percentage.** The rate is stored as a fraction, so 0.0810 rendered as `0.1%` where it should have read `8.1%`. Only the printed label was affected — subtotals, VAT amounts and totals were always calculated correctly. Already-generated PDFs keep the old label until regenerated; see Upgrading if you run a custom template.
- **The chart drew consumption and production in each other's colours.** Anyone reading a bidirectional meter's chart could have taken one for the other. The same fix corrects day and hour labels, which were computed in UTC but printed in local time and could name the wrong day near midnight.
- **Data Quality hid the meters with no readings at all.** A meter that had never received one never appeared, not even as a red row, so a community could look fully covered while a meter sat silent. The tab's meter filter also did nothing when set; both now work.
- **Data Quality named today's assignment holder, not the period's.** Reviewing an earlier quarter showed whoever holds the meter now, so a gap could be raised with a participant who had not yet moved in.
- **Deleting a metering point did not say what it would destroy.** The confirmation named only the meter, while the delete cascades to every reading and the whole assignment history. It now states both counts before you confirm.
- **A production meter's exported energy was labelled "Feed-in".** It now reads "Production" for a production meter and "Feed-in" for a bidirectional one.
- **Hourly resolution over a long period could hang the browser.** A year at hourly resolution is 8,760 bars; hourly is now offered only for periods of 31 days or less.

### Under the hood

The Metering Data page moved onto the shared card, empty-state and loading-skeleton components the rest of the app uses, and the metering endpoints now reject a malformed `metering_point` or date with a 400 instead of raising a 500. The metering analysis and metering points guides were rewritten against the shipped interface.

### Upgrading

No database migrations, configuration changes or deployment steps in this release.

One manual step, and only if you run a **custom invoice PDF template**: the VAT label must use `{{ vat_rate_percent }}` (the rate in percent form) rather than `{{ vat_rate }}` (the stored fraction), or reset the template to the default under **Admin Console → PDF Templates**. Invoice PDFs already generated keep the old label until they are regenerated.

Scripts reading `data-quality-status` should expect more rows than before: metering points with no readings are now included, at 0% completeness.
