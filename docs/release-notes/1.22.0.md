This release lets a participant whose PV system sits behind the meter show
their real self-sufficiency, and hardens sign-up, OAuth, email templates and
downloads. If you sign in through an OAuth provider, read **Security
hardening** before you upgrade.

### Your own energy data

A meter marked **Generation behind the meter** only sees the surplus and the
grid draw, so OpenZEV could not say how self-sufficient that household is. A
participant can now connect the system that does measure it, and the figures
join the statistics. They are **never used for billing**: invoices read the
grid operator's meter data alone, as before.

It is off until an administrator enables `supplementary_energy_data_enabled`
under **Platform → Settings → Functions**. The participant who personally
holds the metering point then finds **Account → Energy data** and connects
either:

- **Solar Manager**, with the installation ID and an API key. OpenZEV checks
  the key before saving anything, fetches new data hourly and re-reads the
  last two days for late corrections. The key is stored encrypted under the
  new `INTEGRATION_ENCRYPTION_KEYS`; without it only the second option works.
- **Push or file**: a push token (shown once) for `POST
  /api/v1/metering/supplementary/ingest/` from Home Assistant, n8n or a
  script, or a CSV upload that is checked first and imported all-or-nothing.

Four values per quarter hour are stored (consumption, production, grid import
and export), only for the time the participant held the meter. The
participant's dashboard gets a **Your own system** card, and the annual
report, the annual statement and the AI assistant tools show the same
self-sufficiency. A rate appears only when 95 % of the quarter hours are
present; with less it stays **—** with the reason, never a misleadingly low
number. After each sync OpenZEV compares the source with the official meter
and tells the participant when they differ or look shifted.

A ZEV manager sees status and figures, and can switch a source off or delete
its data, but cannot connect one or read a key. A manager who is also a
participant sees their own card on the **Energy balance** (marked **You** in
the table), and clicking the selected table row again clears the selection.
Transfer archives (now format 7) can carry the data as an opt-in section; no
key or token travels, and each participant connects again after an import.

Only Solar Manager is supported. The client has not yet been run against the
vendor's live cloud, so watch the first sources for the **Problem** status. There is no
automatic retention, and a source ends by itself when the participant's
assignment ends. Chapter 20 of the user guide has the push format and a Home
Assistant example.

### Security hardening

- **OAuth:** creating or matching an account now requires the provider to
  return `email_verified: true`. A provider that verifies email but omits the
  claim needs **Allow missing email-verification claim** on its entry, which
  covers new accounts only. Token and userinfo endpoints must be HTTPS,
  public, and must not redirect. If yours is in-cluster or private, set
  `OAUTH_ALLOW_PRIVATE_HOSTS=True` (all providers; HTTPS stays required).
  Make sure an admin has a working alternative login before you upgrade.
- **Django's own `/admin/` login** is off in production
  (`DJANGO_ADMIN_ENABLED` defaults to `DEBUG`). Normal administration is
  under **Platform** and is unaffected; the default Helm routing keeps `/admin/`
  on the frontend.
- **Custom email templates** are limited to 20,000 characters and to plain
  fields; ones using attribute or index access (`{user.secret}`, `{x[0]}`)
  fall back to the shipped default and log a warning.
- **Registration** answers the same way for new, used and invited
  addresses, and resends have a 15-minute cooldown per address (a shared
  cache is required).
- **Invoice prefixes** are 1–10 of `A-Z`, `0-9`, `-`. Existing ones keep
  working; the upgrade prints any that do not match (see Upgrading).

### Also new

- Confirmation dialogs cannot be submitted twice, and **Cancel** becomes
  **Close** while an action is running. Escape closes a dropdown or calendar
  before its dialog.
- The email history is a dialog, and the balance charts stack on narrow
  panels.

### Under the hood

ADRs 0030 and 0031 record why supplementary data is kept out of billing and
why its credentials sit under their own key.

### Upgrading

Three migrations, none rewriting data: `metering` 0007 creates the two
energy-data tables, `accounts` 0022 adds the OAuth trust option (off), and
`zev` 0043 only **prints** ZEVs whose invoice prefix is now invalid, to be
changed before the next invoice.

**Configuration.** `INTEGRATION_ENCRYPTION_KEYS` (Helm
`integrationEncryptionKeys`, needed by backend and worker) is optional. Keep
old keys in the list when rotating and run `manage.py rotate_integration_key`.
`OAUTH_ALLOW_PRIVATE_HOSTS` and `DJANGO_ADMIN_ENABLED` are described above.
Optional tuning: `SUPPLEMENTARY_SYNC_INTERVAL_S`, `SUPPLEMENTARY_MIN_COVERAGE`.

**Breaking changes:**

- Transfer archives are format 7, which 1.21 cannot import.
- `POST /auth/register/` no longer tells a caller whether the address exists.
- Dashboard, annual report and metering point responses gain nullable
  `gross_energy` fields, `null` while the feature is off.
