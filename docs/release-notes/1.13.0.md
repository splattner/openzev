This release adds dynamic tariffs — an energy tariff priced from the grid operator's published series instead of fixed bands — and removes every password OpenZEV used to hand a participant, replacing it with a revocable sign-in link. Two things need a decision on upgrade: every deployment now runs an additional Celery Beat container, and the feasibility calculator ships off by default.

### Bill from a dynamic tariff

Under **Setup → Tariffs**, an energy tariff can take a **Dynamic price source** instead of price bands: give it an operator's price URL, confirm the detected component and product, and it re-fetches every four hours.

Prices are stored, not cached — operators keep little history themselves (Groupe E drops it after nine months, BKW none at all), so an unstored interval is gone for good. **View prices** shows what's on hand:

![Price history for a Groupe E vario grid-usage source over one week: 672 quarter-hourly points averaging 0.07037 CHF/kWh, 121 of them negative, no coverage gaps, charted as a line swinging between roughly 0.165 and −0.05 CHF/kWh](screenshots/1.13.0-price-history.png)

Where the series has no price for a reading, invoice generation refuses rather than billing it at zero — nothing partial is written, a bulk run reports it as that participant's failure, and readiness flags the gap before you even try.

Once generated, an invoice keeps its own record of the price it billed, so repointing, revising, or deleting the tariff's source afterward can't erase it — the source stays undeletable while any invoice still refers to it. Two other limits: a dynamic tariff has no headline rate, so PDFs print the fetched average, footnoted as approximate; and the VSE importer won't guess a product — Groupe E's `vario` and `double` differ — so an imported candidate needs you to pick one.

### Managing price sources

A source is shared across every community — one public endpoint, one set of prices — so sources live under **Platform administration → Overview → Dynamic prices**, not inside a ZEV:

![The Dynamic prices tab, listing a Groupe E vario grid-usage source with its health, last fetch, stored point count, and the tariffs and ZEVs using it](screenshots/1.13.0-dynamic-sources.png)

Admins can fetch on demand, backfill history, re-check capabilities, and rename a source. Clearing prices is refused while a non-cancelled invoice overlaps them, and a source can't be deleted while any tariff still points at it.

### Suggest a grid operator from a postal code

**Setup → Settings** now takes a **Postal code** for the grid connection and suggests the operator from ElCom's register — 3,172 postal codes across 553 operators, resolved against a checked-in copy, not a live lookup.

For 448 operators with a machine-readable tariff address, it can also fill in the import URL once a fetch confirms the address still serves one — these rot between an operator's re-upload and ElCom's refresh. Nothing is written without your click, and an existing URL is never overwritten.

### The feasibility calculator is off by default

The vZEV feasibility calculator, in the sidebar since 1.4.0, sits behind a feature flag that ships off — it disappears from navigation and its endpoints return 403 until enabled under **System Settings → Feature Flags**, or via `FEATURE_FEASIBILITY_CALCULATOR_ENABLED=true`.

### Participants sign in without a password

Under **Setup → Participants**, each participant shows whether they've been invited, are active, or had their link revoked, with **send**, **copy**, and **revoke** actions. The link signs them into their own account, works until revoked, and no password is ever shown, typed, or emailed.

This replaces every password OpenZEV used to issue a participant — creation no longer shows one, and **Create account** (**Platform administration → Accounts**) returns a link instead, revoked when you unlink the account. The invitation email template is gone; its replacement is editable under **Platform administration → Templates → Onboarding Email**.

### Also new

- Your selected community is remembered on your account instead of in the browser, so it follows you between browsers and no longer carries over to the next person on a shared device.

### Fixes worth knowing about

- **One account's data could show up under another in the same browser tab.** Cached queries weren't keyed by identity, so a request still in flight when you logged in, logged out, or toggled impersonation could resolve afterward into the new account's view. All four boundaries now clear the cache first. Nothing was written to the database, but if you share a browser or use impersonation, some on-screen figures may have belonged to someone else.
- **A bank IBAN with no owner address on file silently dropped the QR payment slip** — true since the first release, since nothing checked the IBAN's format or required an address. **Billing & payment** now validates both; if you've had an IBAN set, check a recent invoice for its QR code.

### Under the hood

ADR 0018 and ADR 0019 record why dynamic prices are stored globally as evidence and frozen onto the invoice rather than looked up live. `docs/specs/2026-09-dynamic-tariffs.md` covers the fetch, pricing and import paths end to end.

### Upgrading

**Every deployment now runs a Celery Beat scheduler**, and dynamic price refreshes won't happen without it. The Compose stacks gain a `beat` service, the Helm chart a single-replica Beat `Deployment`, on by default — keep `beat.replicaCount: 1`, since a second scheduler double-enqueues every task. No Beat shipped before, so the OAuth-token and export-artifact sweeps also start running for the first time.

Ten migrations, all additive, across five apps: **zev** (2) — postal code, and the onboarding-link table; **tariffs** (4) — the price-source tables, a protocol reshape, and two validity constraints, no-ops on the empty tables; **invoices** (2) — the price-evidence table (auto-backfilled, empty without dynamic tariffs) and one dropping the invitation template; one each in **accounts** (preferred community) and **audit** (the onboarding-link source).

**Removed:** `send-invitation` and `create-account`'s password fields, replaced by `send-onboarding-link` / `onboarding-link` / `revoke-onboarding-link` — update scripts using the old `{username, temporary_password}` shape. Existing tariffs and accounts are otherwise unaffected; no downtime is expected.
