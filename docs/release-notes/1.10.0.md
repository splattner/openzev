This is a small release. Its one new capability is a printable tariff
overview: the prices a ZEV charges, as a PDF you can hand out or file. It also
fixes a crash on the metering-point form and cuts the database work a batch
billing run repeats.

### Tariff overview PDF

Every other participant-facing document a ZEV produces — invoice, annual
statement, financial summary, participation contract — has a printable form.
The tariffs did not: they existed only as rows on the **Tariffs** page, behind
a login. That left four situations with no good answer — a participants'
meeting where prices are what people ask about, a price change to communicate
after an Art. 7b import, the archive ("what were our prices on this date"), and
a participant checking a bill.

**Tariffs → Tariff overview (PDF)** on the page toolbar now downloads a PDF
listing every tariff in force today, grouped by category (Energy, Grid fees,
Levies, Metering) in the same order an invoice groups its line items. Owner and
admin only.

- **One row per price band**, named with the same wording as the participation
  contract and the band-itemised invoice added in 1.9.0: HT/NT, a seasonal
  band's month range, a plain band's weekday-and-time window. One band, one
  name, across all three documents.
- **A percentage-of-energy tariff** prints its formula — e.g.
  `18.00 % × 29.50 Rp./kWh` resolving to `5.31 Rp./kWh` — derived from the same
  grid tariffs the participation contract uses, via a helper now shared by both
  documents. Where that grid tariff has more than one band, a footnote says the
  figure shown is the base rate, not the per-timestamp price the billing engine
  actually resolves.
- **Prices are shown in Rp./kWh**, the convention on the contract and on every
  Swiss tariff sheet — not the five-decimal CHF/kWh the invoice carries because
  it multiplies by consumption.
- **A shared fee** states how it is split (equally, or by weight) and prints
  what the whole community pays, not one participant's share — otherwise the
  number reads as a per-participant amount and is wrong by the size of the ZEV.
- **The document states the ZEV's VAT treatment.** Under VAT-inclusive mode the
  stored prices are net and the invoice grosses them per line, so a note says
  the prices here are net — the number on this document is deliberately not the
  number a participant is billed. For a VAT-registered ZEV the note says prices
  exclude VAT and prints the VAT number.
- **To include superseded and future versions**, switch the page's own
  validity filter from "Valid only" to "All tariffs" before downloading; those
  rows print greyed out with their full validity span instead of "from …".

What it deliberately does not do: there is no date picker — the overview always
reflects today (the endpoint accepts an `as_of` parameter, so a picker is a
later frontend-only addition if it is wanted). It is not a customisable
template, matching the financial summary. There is no per-kWh "what a grid
consumer pays" summary line yet, and no price-history chart. No model changes
and no migration — it is a straight projection of stored tariff data.

### Fixes worth knowing about

- **Editing a metering point could blank the page.** Toggling the **Active**
  switch on the metering-point form a second time threw an error that unmounted
  the page: the handler read `event.currentTarget` inside a deferred state
  update, by which point React had nulled it. The first toggle worked, the
  second crashed. The same pattern was corrected on the assignment form's
  dropdowns and on the admin OAuth "enabled" switch. No data was affected and
  the page recovered on reload, but the edit could not be completed.

### Under the hood

Batch document generation — invoice batches, invoice-PDF batches and
annual-statement ZIPs — rebuilt the same ZEV-wide calculations (participant
weight windows, per-date and per-tariff weight sums, community totals) once for
every participant. Each batch now builds them once per ZEV-period and reuses
them; single-document generation is untouched. On the 12-participant fixture
the SQL statement count per batch drops by roughly 15–50% — an invoice-PDF
batch goes from 256 to 131 — though wall-clock time is dominated by PDF
rendering and moves only a few percent. Per-document failure isolation
(ADR 0011) is preserved: a failure in the shared setup is logged once and still
produces one failure entry per affected participant.

### Upgrading

No migrations, no configuration changes, no downtime.

**One behaviour change for API clients.** The annual-statement ZIP endpoint now
returns HTTP 500 when the shared yearly calculation fails, instead of HTTP 200
with an empty archive. A client that checked only the status code was
previously handed a valid-looking ZIP with no statements in it.
