This release adds a read-only MCP server so an AI assistant can answer
questions about your ZEV's data, and reworks how the ZEV settings and
template editors show what is saved. If you run OpenZEV in production, read
the first fix below before you upgrade: backups now refuse to run without an
encryption key unless you opt out.

### Ask your data questions in plain language

OpenZEV can now answer questions about your own data through an AI assistant
— Claude Code, Claude Desktop, Cursor, n8n, or any other client that speaks
the [Model Context Protocol](https://modelcontextprotocol.io). Instead of
clicking through the readiness cockpit, invoice detail, import logs and audit
log, you ask: *"Is Q2 ready to bill for ZEV Sonnenhof?"* or *"Why is this
invoice higher than last quarter?"*.

The server is **read-only** — no tool can create, change, approve, send or
delete anything — and it is off by default. An admin turns it on under
**Platform → System Settings → Functions** (`mcp_server_enabled`), then each
admin or ZEV owner connects with their own API key, ideally one created with
**Read-only key** ticked. The assistant sees exactly what that key's account
can see through the API, contact data (email, phone, address, IBAN) is never
returned, and every question it asks is recorded in the audit log with a new
`MCP` source. Ten tools are available, covering ZEVs and participants,
billing readiness, invoice lookup and explanation, import troubleshooting,
consumption and self-consumption figures (down to hourly buckets for up to a
week), data-gap detection and the audit trail. Participants cannot use it,
and it is not yet reachable from claude.ai directly — that needs an
authorization layer this release doesn't build. See **Connecting an AI
Assistant** in the user guide for setup per client.

### Settings and templates show what's saved

The **ZEV Settings** page and the platform's PDF/email template editors used
to make it easy to lose an edit or not know whether you were looking at a
default or your own customization. Both now make the saved state explicit.

ZEV Settings replaces its per-tab save buttons with a single **Save
changes** / **Discard changes** bar that covers every tab; your edits survive
switching tabs or refreshing the page instead of disappearing with them.
Invoice-email fields and the PDF/email template editors now label whether
you're looking at a built-in default, a platform customization, or your
ZEV's own override, with **Customize** and **Use platform default** actions
to move between them. Resetting a template to the platform default names it
and asks you to confirm first. A server validation error, such as a subject
line that's too long, appears beside the field that caused it and scrolls
that editor into view. Switching to a different community with unsaved edits
now asks you to confirm before discarding them.

### Fixes worth knowing about

- **Backups written without encryption are now refused in production.**
  Previously, a production instance with no `BACKUP_ENCRYPTION_KEYS`
  configured would silently write plaintext archives — full of password
  hashes and personal data — for manual, scheduled and pre-restore safety
  backups alike. `BACKUP_REQUIRE_ENCRYPTION` now defaults to `not DEBUG`, so
  a production instance refuses to create any backup until a key is set. If
  your instance creates backups, check whether `BACKUP_ENCRYPTION_KEYS` is
  configured; if not, see **Upgrading** below.
- Long participant names in the dashboard's energy flow chart, and in the
  Feasibility Calculator that shares it, were cut off past roughly 20
  characters. Names now wrap onto a second line, truncating to `…` only
  beyond that, with the full name in a tooltip.

### Upgrading

One migration, in `audit`: it adds `mcp` as an audit-event source choice.
Additive, no data rewrite.

**Configuration changes:**

- New feature flag `mcp_server_enabled` under **Platform → System Settings →
  Functions**, off by default — no action needed unless you want the MCP
  server.
- `BACKUP_REQUIRE_ENCRYPTION` now defaults to `not DEBUG` instead of always
  being optional. A production instance (`DEBUG=False`) without
  `BACKUP_ENCRYPTION_KEYS` set will refuse to create backups after this
  upgrade, including the safety backup a restore takes first. Either
  configure a key or set `BACKUP_REQUIRE_ENCRYPTION=False` explicitly to
  keep the previous behavior. In the Helm chart, set it through `extraEnv` on
  both the backend and the worker.

**REST change (additive):** the invoice list endpoint gains optional
`participant_id`, `period_from` and `period_to` filters.

No removals or breaking changes.
