Participants can now reach their own data from the invoice they were sent,
without an account — off until you turn it on, and no upgrade turns it on for
you. Alongside it, two long jobs stop happening invisibly: the whole-ZEV annual
statement export and the invoice PDFs. The export **removes an API endpoint**,
so read Upgrading if you script it.

### Participants can open their invoice without an account

Until now the only way in was an invitation email carrying a username and a
generated password the participant then had to change — three steps before
someone who looks at their electricity twice a year sees a number, so most
never did.

Switch on **Participant QR code on the invoice** under **Manage (v)ZEV →
Settings → General ZEV Settings**, and every invoice you generate carries a
second QR:

![A pale green card on the invoice's insights page: a QR code beside the heading
"Rechnung online ansehen", the line "Code scannen und diese Rechnung mit dem
Verbrauch im Detail ansehen – ohne Konto und ohne Passwort", and in bold "Dies
ist kein Zahlungscode"](screenshots/1.11.0-invoice-qr.png)

Scanning it opens that invoice: the total, whether it is paid, the line items
grouped as the PDF groups them, the consumption figures, and the same three
charts the insights page prints — period comparison, average daily profile and
the energy-flow diagram. From there, **Send me a sign-in link** emails one to
the address you have on file, which opens the ordinary participant portal.
Nobody sets a password at any point. The page and that email are both in the
ZEV's invoice language whatever the reader's browser is set to, and you can
reword the email under **Admin Console → Email Templates**.

The QR never shares a sheet with the QR-Rechnung, and is smaller and captioned
"this is not a payment code" in all four languages. An invoice with no
consumption gets none at all.

What the link deliberately cannot do: reach any other invoice, name any other
participant beyond what the flow diagram already prints on the paper, or change
anything. It never expires, so **Revoke link** on the invoice's detail page is
how you stop one that went astray; short of that, a regenerated PDF keeps the
QR already in the post. Requesting a sign-in link never lets the requester
choose the destination, so there is no way to probe whether an address exists.

### Annual statements now prepare in the background

Downloading every participant's annual statement used to hold the browser open
while the server rendered the whole set — minutes on a large ZEV, and a reload
lost the operation entirely.

On **Reports**, **Prepare Annual Statements (ZIP)** now queues the work and
comes back immediately. The card offers **Download All (ZIP)** once the archive
is ready, and you can close the page and return to it. If a participant's
statement could not be generated, the card says how many were left out and names
them in `omitted.txt` inside the archive.

A finished download is kept for 24 hours and then deleted; **Prepare a New
Export** builds a fresh one against current data, which is also how you pick up
a corrected meter reading. Downloading your own statement as a participant is
unchanged — that is one document, and it still arrives immediately.

### You can see an invoice's PDF being made

Rendering happens in the background, so an invoice appeared with its **PDF**
column reading *Missing* and the document arrived at some unannounced later
moment. A render that *failed* looked exactly the same, and stayed that way.

The column on **Invoices** now shows **Generating…** while a document is being
produced, and the page refreshes itself until every one has arrived rather than
waiting for you to reload. A render that fails says **Failed**, which it never
could before — use **Regenerate PDF** on that row to try again.

Upgrading marks every invoice that already has a document as ready; the rest
keep reading *Missing*. **Failed** appears only for renders that fail from here
on, so no old invoice turns red on upgrade.

### Upgrading

Seven migrations, all additive, no downtime expected:

- `zev.0024_zev_participant_invoice_access` — the opt-in flag, off for every
  existing ZEV. Nothing changes on your invoices until you tick it.
- `invoices.0014_invoiceaccesstoken` and `invoices.0015_invoiceaccesstoken_secret`
  — the per-invoice link. Both ship in this release, so 0015 has nothing to
  rewrite on an instance upgrading from 1.10.
- `accounts.0013_magiclinktoken` — the one-time sign-in link.
- `audit.0004_alter_auditevent_source` — adds an `invoice_link` audit source, so
  the log names the printed credential rather than only reporting "api".
- `exports.0001_initial` — the job table behind the annual-statement export.
- `invoices.0016_invoice_pdf_status` — tracks whether a document is pending,
  ready or failed, and backfills `ready` for every invoice that already has one.

**Removed: `GET /invoices/invoices/annual-statements-zip/`.** If you script the
whole-ZEV download it now returns 404. The replacement is three calls: `POST
/exports/jobs/` with `{"export_type": "annual_statements", "zev_id": "…",
"params": {"year": 2026}}`, then poll `GET /exports/jobs/{id}/` until it reports
`completed`, then `GET /exports/jobs/{id}/download/`. The single-participant
annual statement endpoint is untouched.

**Two new optional settings.** `EXPORT_RETENTION_HOURS` (default 24) is how long
a finished ZIP stays downloadable; `EXPORT_RUNNER_TIMEOUT_S` (default 1800)
bounds one export before it is recorded as failed. Export jobs run on the Celery
worker you already run and write to the media volume the web service and worker
already share, so there is nothing new to deploy.

**The opt-in does not travel in a transfer archive.** An imported ZEV arrives
with it off, whatever the exporting instance had, because an import must never
grant access to anything.

Opening an invoice from its link records one audit event per link per hour, so
the log shows that a bill was read without filling with one person's refreshes.
