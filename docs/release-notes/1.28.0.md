This release adds live energy data: what your community produces and uses right now, and when the sun is expected to deliver. It is **an early version for testing, switched off by default**, and nothing in it touches billing. It also corrects how percentage tariffs are billed when your ZEV folds non-recoverable VAT into its prices. If that is you, read the first fix below before you generate the next period.

### Live energy data (testing only, behind a feature flag)

Live energy data is not yet considered stable. Use it to try it out on a test instance or on a community that is happy to be the first. Screens, settings and the way sources are connected may still change between releases.

An administrator switches it on in **Platform → Settings → Functions** (flag `live_energy_data_enabled`, or `FEATURE_LIVE_ENERGY_DATA_ENABLED=true`). It also needs the energy data feature, which is on once `INTEGRATION_ENCRYPTION_KEYS` is set. While the flag is off, the live endpoints answer `404` and no live screen appears; existing energy data sources are untouched.

Once on, the sidebar gains **My energy system** for participants and **Live energy** for managers and viewers. **Right now** sits at the top: your own consumption and production, then the ZEV's production, consumption, spare power and local share, in kW. Below it, **Today** draws the day's curve, **Tomorrow** the production forecast, and **7 days** and **Period** show your own system's history.

A metering point reports its current power from a device you already run. A participant connects their own meter under **My metering points → Connect**; a manager connects meters nobody holds personally and the grid connection point under **Setup → Settings → Energy data**. Two ways in:

- **Push.** Home Assistant, a Shelly script or any device that can send an HTTP request posts the current power in watts to `POST /api/v1/metering/live/ingest/` with the source's push token. A source may send at most once every 5 seconds.
- **Solar Manager.** OpenZEV reads the current power from your account about every 30 seconds, but only while someone has the live page of that community open.

The **production forecast** needs roof planes (kWp, tilt, direction) on the producing metering point, found in its row menu under **Roof planes**, and the building's coordinates. **Connect forecast** then uses the free forecast.solar service, or Solar Manager's own forecast if the plant is connected there. Only the location, rounded to about a kilometre, and the roof planes leave your instance. forecast.solar reaches today and tomorrow, Solar Manager three days.

What it deliberately does not do:

- **Nothing is estimated.** A value older than 60 seconds counts as missing. The split of consumption into local and grid appears only when it can be computed exactly: when every consuming point reports, or, in a physical ZEV, when the grid connection point does. Otherwise you see the ZEV's production and a note, not a guess.
- **Nothing is stored as history.** Live values live in the cache (Valkey) for 48 hours, for today's curve. A cache restart empties the curve.
- **Nothing reaches an invoice.** Billing keeps using the grid operator's data alone.
- **Participants never see another participant's use.** Managers see each metering point.

The full description is in [Your Own Energy Data](https://www.openzev.ch/docs/20-energy-data/) and ADR 0044.

### Also new

- Energy data sources can now provide history, live values and a forecast independently, so one connection per meter can carry several. Existing sources keep working as history sources.

### Fixes worth knowing about

- **Percentage tariffs under-billed in ZEVs that fold VAT into prices.** If **Settings → General → VAT treatment** is *Not registered — fold non-recoverable VAT into prices* and you have a percentage-of-energy tariff (for example "65% of the grid price"), the percentage was taken of the grid price **without** VAT, while the grid lines it undercuts carry VAT. The local price came out lower by the VAT rate. It is now taken of the grid price with VAT; producer credits use the same base, so charge and credit for the same kWh still net to zero. Issued invoices are unchanged. **Newly generated periods bill the local price about the VAT rate higher than before**, so check drafts you generated earlier and regenerate them. The tariff overview and contract PDF still print the net grid price as the example base.
- **The MCP tools `find_invoices` and `explain_invoice` failed for any invoice with a generated PDF.** The PDF link was built from the wrong host name behind a reverse proxy and rejected. They now use the host the assistant called. If you gave an assistant access through the [MCP endpoint](https://www.openzev.ch/docs/19-ai-assistants/), these tools work again.

### Upgrading

Three migrations, all additive, no downtime expected:

- `metering.0012`: new fields on energy data sources for what a source provides and what it targets; the community link is filled in from existing sources
- `metering.0013`: the stored production forecast
- `zev.0048`: building coordinates and roof planes

New optional settings, all with working defaults: `LIVE_MAX_AGE_S` (60), `LIVE_MIN_PUSH_INTERVAL_S` (5), `LIVE_PULL_INTERVAL_S` (30), `LIVE_PUSH_THROTTLE_RATE` and `LIVE_READ_THROTTLE_RATE`, `FORECAST_REFRESH_INTERVAL_S` (3600), `FORECAST_HORIZON_H` (72), and `FORECAST_SOLAR_API_KEY` for a paid forecast.solar plan. Two new Celery beat tasks run (`poll-live-sources`, `refresh-production-forecasts`); both do nothing while the flag is off, but the worker and beat must be restarted to pick them up.
