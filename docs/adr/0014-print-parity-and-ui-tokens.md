# ADR 0014: Print parity via shared tokens and real-PDF previews

- Status: Accepted
- Date: 2026-08-23
- Related specs: `2026-08-ui-redesign-pdf-style` (baseline), `2026-08-contract-pdf-redesign` (PDF design system), `2026-04-frontend-management-page-design` (CRUD shell)
- Related ADRs: 0001, 0003, 0007

## Context

Two product languages diverged:

*   **Screen:** React 19 + TS + Vite; hand-rolled `frontend/src/index.css` (~43 KB, ~211 raw hexes) + Mantine v9 with a sky-blue ramp (`#0284c7`, `#f0f9ff`→`#0c4a6e` in `frontend/src/main.tsx:24-43`) + MUI Data Grid on `ImportsPage`/`AdminInvoicesPage`. Recharts charts via a 2-constant `frontend/src/lib/chartTokens.ts`. Slate `#0f172a` sidebar shell. `frontend/src/App.css` is unreferenced Vite scaffolding. Both `@mantine/dates` and `@mui/x-date-pickers` are dependencies.
*   **Print:** WeasyPrint → PDF/A-3b (`invoices/pdf_render.py`); a single coherent forest/ink/paper system in `backend/templates/pdf/shared_pdf_base.html:23-42` (`--brand-deep #0d2b1d`, `--brand #143828`, `--brand-mid #1f5c3a`, `--gold #bfa05a`, etc.) shared by `invoices/invoice_pdf.html`, `contracts/participant_contract_pdf.html`, `invoices/annual_statement_pdf.html`, `invoices/financial_summary_pdf.html`; Swiss QR-Rechnung as a `106mm` `@page` running element (`position: running(qr-slip)` + `@page invoice-payment { margin-bottom: 106mm; @bottom-center { content: element(qr-slip) } }`); charts as injected SVG (`invoices/pdf_charts.py:7-18`) with heavy mm-tolerance layout tests.

The PDF preview is structurally wrong: `POST /api/v1/invoices/invoices/preview-pdf-template/` returns `{ html }` rendered with sample contexts from `invoices/template_context.py` and `frontend/src/pages/AdminPdfTemplatesPage.tsx` does `iframe.contentDocument.write(html)`. Browsers ignore `@page`, margin boxes, `position: running(...)`, mm geometry and WeasyPrint font handling — the preview can never match the shipped PDF. `InvoiceDetailPage` has no document preview even though `Invoice.pdf_file`/`pdf_url` stores the artifact. There is no token sharing between screen and print.

Brand requirement: one product family — screen-first, print-faithful. One product brand for every ZEV (no per-ZEV theming). Playwright screenshot automation (`screenshots.config.ts`, de-CH, 1440×900) already feeds `docs/user-guide/screenshots/` and `README.md`; `pr-quality.yml` runs frontend lint/test/build.

## Decision

1.  **Screen-first, print-faithful — sibling, not parent.** Share tokens, brand and chart palette by construction; do not copy layout grammar 1:1. Helvetica 9.5pt, uppercase eyebrows on every label, document-header anatomy as page chrome, amount-card gradient on every button, and `position: running()` machinery stay print-only/on-dark-only. Screen keeps `Inter Variable` and a functional hierarchy (page title 1.5–1.75rem/650/−0.02em, labels 0.75–0.8125rem/500, uppercase only for true kickers). Gold `#bfa05a` is decorative/display on dark only (see consequences re contrast).
2.  **One token source, generated outputs.** `design/tokens.json` is the SSOT (primitives = PDF hexes verbatim plus `--white` and the status fills, so semantics never contain raw hex; semantics like `--app-bg`, `--surface-card`, `--border-default`, `--text-*`, `--interactive`, `--focus-ring`, `--status-*`; `themes`: empty (the default theme is expressed by `semantics` directly, emitted as `:root` — alternates are deferred until a tested use case exists, themes stay data); `charts` mirrors `pdf_charts.py`; `type` holds font-family only). Generator `scripts/generate-tokens.mjs` emits five committed outputs: `frontend/src/styles/tokens.css` (`:root` map), `frontend/src/styles/generatedTheme.ts` (Mantine theme — imported by `main.tsx`, which stays hand-written), `frontend/src/lib/chartTokens.ts` and `backend/invoices/generated_chart_tokens.py` (both resolved literal strings — Recharts/SVG and Python cannot resolve `var(…)`; `pdf_charts.py` imports the generated module, no duplicated literals), and `backend/templates/pdf/_tokens.css` included by `shared_pdf_base.html`. Components reference semantics (`var(--surface-card)`) only. Enforcement per surface: `stylelint` `color-no-hex` on frontend CSS (generated `tokens.css` allowlisted), and the `scripts/check-frontend-hex.mjs` color sweep on hand-written TSX/TS, backend PDF/HTML templates and `invoices` Python — the sweep flags raw hex *and* raw `rgb()/rgba()/hsl()/hsla()` literals (an `rgba()` legacy sky-blue once slipped through a hex-only regex); neutral alpha scrims/shadows are sanctioned per file via `"path@alpha"` entries in its allowlist, while hex and opaque `rgb()/hsl()` are never allowlistable. Generator `--check` + idempotence test for the JSON/Python side.
3.  **Preview the shipped bytes.** `POST /api/v1/invoices/invoices/preview-pdf-template/` keeps `200 { html }` as a debug toggle (rendered by the frontend as escaped source text — never executed in an iframe) and gains a body param `output: "pdf"` → `200 application/pdf` via the existing `render_pdf()` (PDF/A-3b) and the existing sample contexts. Admin editor fetches as `blob` → `URL.createObjectURL` → `<iframe>` (native viewer gives A4 fidelity; debounced 700 ms, revision guard + `AbortController` so out-of-order renders never win, revoke on replace). Parity means same renderer/template/tokens/PDF profile — not byte-equality with issued documents (sample data, timestamps, IDs differ). No tenant scope (sample data). Invoice/contract/annual-statement detail pages embed the real artifact in a paper frame via a new `frontend/src/components/PdfPreview.tsx`, always through authenticated blob fetch + object URL (uniform for cookie/token auth and for `Content-Disposition: attachment` endpoints); generate-if-missing reuses `POST /invoices/{id}/generate-pdf/`.
4.  **Re-skin in place; no new UI library; one styling-system trajectory that ends with less code.** Stay on React. No new MUI outside the two Data Grid pages; dates/comboboxes/overlays = Mantine — the five MUI date-picker call sites are cut over to Mantine during the rollout and `@mui/x-date-pickers` is removed. Existing CSS contracts (`.page-stack`, `.card/.table-card/.stat-card`, `.button*`, `.badge-*` from `2026-04-frontend-management-page-design.md:100-112`; `StatCard`, `ActionMenu`, `FormModal` from `:45`, `:92-96`) are the design system — extend, don't duplicate. Phase 5 (own ADR, after the visual language is stable): replace MUI Data Grid with TanStack Table + own table CSS, swap the last MUI widgets for Mantine, and retire every `@mui/*`/`@emotion/*` package. Delete `frontend/src/App.css`.
5.  **One product brand, no per-ZEV branding.** Every ZEV shares the same forest/ink/paper brand. No per-ZEV logo/color, no ramp derivation, no tenant theme switcher. Operators never set 12 colors. This can be revisited only if a customer-funded closed theming system replaces free-form template overrides.
6.  **Dark mode deferred** (semantic layer keeps it cheap). Phased rollout with independently mergeable PRs: Phase 0 mockups gate (code-only previews via `/design-preview/*` + Playwright PNGs at 1440×900 de-CH), Phase 1 tokens+chrome+real preview, Phase 2 table/card/pill/empty-state pass + MUI date-picker cutover (`@mui/x-date-pickers` removed), Phase 3 page-by-frequency pass, Phase 4 contrast/focus/keyboard/locale/axe and screenshot regeneration, Phase 5 MUI retirement (TanStack Table; gated on Phase 4 acceptance).

## Consequences

Positive:
- Parity by construction — a design change lands in one file (`tokens.json`) and all five outputs regenerate; hex drift between screen and print becomes a failing `node scripts/generate-tokens.mjs --check` / token-idempotence test.
- Preview is WYSIWYG because it runs the exact production pipeline — same renderer, template version, tokens and PDF profile (byte-equality with issued documents is not claimed; sample data, timestamps and IDs differ). Users approve what ships; admin template editor and document detail no longer maintain two diverging render paths.
- Palette and chart colors unify (PDF SVG and recharts share the same `charts` block), improving comprehension across dashboards and invoices.
- Readability gains without losing brand: sidebar moves slate→forest (`#0f172a`→`#0d2b1d`), sky gradient/radials drop, typography disciplined, tables gain sticky header + tabular-nums + right-aligned money + consistent selected state.
- Net code and dependency reduction, not a re-theme: `@mui/x-date-pickers` drops in Phase 2, all `@mui/*`/`@emotion/*` packages are retired in Phase 5, and a dead-rule sweep is accounted for at Phase 5 close-out — mid-rollout `index.css` has actually grown (+195 lines at the Phase 4 mark), because the new table/pill/preview contracts outweigh the deletions so far. The end state remains one date system, one styling system, less frontend code.

Trade-offs:
- Generator is extra indirection early (SSOT before visuals are locked). Mitigated by gating on code-only mockup acceptance (Phase 0) and keeping the generator small, schema-validated, with a single idempotence test.
- WeasyPrint preview is slower than HTML write; debounce + keep-last-render + HTML debug toggle + error banner trade latency for correctness.
- `stylelint color-no-hex` initially allows the generated files; tightening too early would block the migration. Rule lands in Phase 1 and narrows to the generated token outputs only once the sweep is done.
- Gold `#bfa05a` on white is contrast `~2.8:1`, failing WCAG AA `4.5:1` (`3:1` for large text). Mitigated by restricting gold to display on dark (`var(--brand-deep)` at ≥16pt or ≥14pt/700) and as 1–2px accents — the PDF already obeys this (`savings-row.highlight` on dark at `9pt/900`); Phase 4 axe `AA+` gate enforces it.

## Alternatives considered

1.  **Svelte rewrite** — large-scale churn across ~25 pages + TanStack Query + i18n×4 + Mantine dates + Data Grid + recharts + leaflet, with zero design gain; the same token problem would have to be solved anyway.
2.  **Typst compiler** — fast and typographically strong (recent versions emit PDF/A-3b), but severs the HTML/CSS bridge that makes print↔web parity cheap, kills the admin HTML editor, and forces re-proving the QR-Rechnung `106mm` running-element layout. Revisit trigger: dropping free-form HTML overrides for a closed, code-owned document system.
3.  **Consolidate fully on Mantine** — large-scale churn for a styling change; hand-rolled contracts already function as the design system to extend.
4.  **HTML facsimile of the invoice on the detail page** — two sources of truth that drift; superseded by embedding the real PDF (decision 3).
5.  **Per-ZEV branding (logo + one color → derived ramp, or operator-set 12 colors)** — deferred indefinitely. It fragments the family, complicates tokens/themes (tenant switcher, ramp generation, contrast audits per tenant) and is orthogonal to readability/preview gains. Not in scope until a funded closed theming requirement appears.
